# 歌曲文件归档设计

> 本轮归档规范。与《产品需求》§6 模板整理冲突时，**以本文为准**；§6 模板整理降级为后续可选的高级整理（待办 #1/#2）。
>
> 已定决策：
> 1. 归档目标统一为 `archived/{歌手}/`，纳入库管理与「整理」按钮都走它
> 2. `Unarchived/` 是待整理区，**音频仍入管理表**，便于选中后归档
> 3. 版本括号说明**保留原文件名**；目标冲突时不自动改名，提示用户手动处理

## 1. 库目录结构

初始化 / 首次扫描时创建（已存在则跳过）：

```text
库根/
  axmusic.db              # 工作库（已有）
  archived/               # 歌曲归档区（规范位置）
    {歌手}/
      歌手 - 歌名.flac
      歌手 - 歌名(说明).flac
  lrc/                    # 外挂歌词（扁平，已有）
    歌手 - 歌名.lrc
    歌手 - 歌名(说明).lrc
  covers/                 # 封面缓存（已有，含 .thumbs/）
  playlists/              # m3u8 歌单（已有）
  Unarchived/             # 待整理区（库根杂项收纳）
```

**允许出现在库根的条目**（白名单）：

| 名 | 类型 |
|----|------|
| `archived` | 目录 |
| `Unarchived` | 目录 |
| `lrc` | 目录 |
| `covers` | 目录 |
| `playlists` | 目录 |
| `axmusic.db` | 文件 |
| `axmusic.db-wal` | 文件（SQLite WAL 伴生，可缺） |
| `axmusic.db-shm` | 文件（SQLite WAL 伴生，可缺） |
| `axmusic.db-journal` | 文件（SQLite rollback journal，非 WAL 回退/崩溃恢复时出现，可缺） |

其余一律视为杂项：音频、歌词、任意文件、任意文件夹。临时文件（`.axtmp-*`）忽略不报。

## 2. 库根杂项扫描（管理页 · 库统计）

### 2.1 检测

只看**库根直接子项**（不递归）。逐项对照白名单，列出杂项清单：

```ts
interface LibraryRootScan {
  ok: boolean;                 // 无杂项
  items: LibraryRootItem[];    // 杂项
}

interface LibraryRootItem {
  name: string;      // 显示名
  path: string;      // 绝对路径
  is_dir: boolean;
  kind: string;      // "audio" | "lyrics" | "other_file" | "other_dir"
}
```

分类仅影响展示图标/文案，处理动作相同。

### 2.2 UI

- 位置：管理页**未选中曲目**时，右栏「库统计」内新增区块「库文件扫描」
- 有杂项：提示「库根有 N 项待整理」+ 列表（文件名，可滚动）+ **整理**按钮
- 无杂项：弱化一行「库根目录整洁」（不占视觉重心）
- 点「整理」→ 全部杂项移入 `Unarchived/` → 重新扫描 → 刷新统计

### 2.3 整理动作

- 目标：`Unarchived/{原名}`；已是目录则整棵移入
- 同盘 `rename`；目标已存在 → 该项失败并保留，汇总提示「N 项成功，M 项因重名未移动」
- 不改 DB、不递归归档；用户之后在管理表选中条目再单曲归档

### 2.4 扫描范围说明

`Unarchived/` **不**被本扫描视为杂项（它本身是白名单目录）。其中的音频由常规「刷新扫描」入 tracks 表。

## 3. 歌曲文件归档规则（单曲 · 对比面板）

### 3.1 命名规范

```text
{artist} - {title}{version}.{ext}
```

| 段 | 规则 |
|----|------|
| `artist` | 标签歌手；空 → `Unknown Artist`；`sanitize_segment` |
| `title` | 标签歌名；空 → 原文件主名；`sanitize_segment` |
| `version` | 可选。**保留原文件名末尾括号说明**，如 `(Live)` `(Remix)` `(2011 Remaster)`；无则不加 |
| `ext` | 原扩展名，小写 |

完整路径：

```text
<库根>/archived/{artist}/{artist} - {title}{version}.{ext}
```

版本括号提取：取原文件名（去扩展名）**末尾**一层括号，形如 `...\s*\([^()]+\)$`；中间的括号不挪作版本号。提取结果原样保留在目标名中。

示例：

| 现状 | 归档后 |
|------|--------|
| `D:\dump\周杰伦 - 晴天.flac` | `archived/周杰伦/周杰伦 - 晴天.flac` |
| `晴天(Live).flac`（标签：周杰伦 / 晴天） | `archived/周杰伦/周杰伦 - 晴天(Live).flac` |
| `01 - 晴天.mp3`（标签：周杰伦 / 晴天） | `archived/周杰伦/周杰伦 - 晴天.mp3` |

### 3.2 检测（扩展现有「归档状态」）

**仅已关联 catalog 的曲目**做归档要求；未刮削/未关联在边栏显示「先要刮削」，管理表归档列显示 `—`。

| kind | 条件 | 文案 |
|------|------|------|
| `song_location` | 父目录 ≠ `archived/{artist}/` | 歌曲不在归档目录 |
| `song_name` | 文件名 ≠ 期望名（忽略扩展名大小写） | 歌曲命名不规范 |
| `lyrics_location` | 现有 | 歌词不在库 lrc/ 目录 |
| `lyrics_name` | 现有 | 歌词命名不规范 |

- 无外挂歌词：歌词两项仍不报
- 无标签歌手/歌名：用回退值参与期望路径计算，仍可检出位置问题
- `ok = issues.is_empty()`

### 3.3 整理（按意见单条处理，不做批量）

**每条归档意见一个「整理」按钮**，只修该条：

| kind | 动作 |
|------|------|
| `song_location` | 移到 `archived/{artist}/`，**保留当前文件名** |
| `song_name` | 就地改名为期望名，**目录不动** |
| `lyrics_location` | 移到 `lrc/`，保留当前文件名 |
| `lyrics_name` | 就地改名为期望名 |

位置、命名都错时点两次即可。歌曲变更仍更新 `tracks.path` 并改写歌单；目标已存在则失败不覆盖。

### 3.4 与「纳入库管理」对齐

`include_in_library` 的复制目标从 lossless-archive 模板改为：

```text
<库根>/archived/{artist}/{artist} - {title}{version}.{ext}
```

`version` 取自**源文件名**末尾括号；冲突时拒绝并提示（与现状「目标已存在，未覆盖」一致）。

## 4. 歌词命名（补版本）

现有规范 `歌手 - 歌名.lrc` 扩展为：

```text
{artist} - {title}{version}.lrc
```

`version` 与对应音频一致。无版本时行为不变。查找顺序仍为：规范化名 → stem 名 → 音频旁 sidecar。

## 5. 代码落点

| 层 | 变更 |
|----|------|
| `paths.rs` | `library_archived_dir` / `library_unarchived_dir`；init 时 `create_dir_all` 白名单目录 |
| `archive.rs` | 增加歌曲 location/name 检查与 normalize；版本括号提取；目标冲突保护；返回新旧路径 |
| `commands.rs` | `library_root_scan` / `library_root_organize`；`archive_normalize` 扩展；`build_library_dest` 改为 archived 方案 |
| `library` | （可选）`file_operations` 记一笔 move |
| `types.ts` | `LibraryRootScan` / `LibraryRootItem`；`ArchiveIssue.kind` 注释补 `song_*` |
| `api.ts` | 对应 invoke 封装 |
| `StatsPanel` | 「库文件扫描」区块 + 整理按钮 |
| `ComparePanel` | 归档状态已复用；整理按钮 title/逻辑覆盖歌曲+歌词 |

不改 scanner 遍历逻辑：仍全库递归，`Unarchived/`、`archived/` 下音频都会入表。

## 6. 边界与约定

- **暂不做批量归档**：一次只整理当前选中曲目；库根杂项整理是唯一批处理
- **不覆盖**：任何 move/rename 目标已存在即失败
- **不自动猜版本**：不从标签推断 Live/Remix；只保留原文件名括号
- **清洗**：统一走 `scanner::sanitize_segment`（替换 `<>:"/\|?*`、去首尾空白/点、保留名加 `_`）
- **跨盘**：库内整理均为同盘 rename；纳入库管理仍是 copy
- **播放不受影响**：改路径后更新 DB 与歌单相对路径；播放会话里的旧路径下次扫描/播放时容错
- §6 模板整理（lossless-archive / flat-by-album / classical）**本轮不实现**，路径也不再作为纳入库管理的默认

## 7. 验收

1. 初始化库目录后存在 `archived/`、`Unarchived/`、`lrc/`、`covers/`、`playlists/`
2. 库根丢入 `歌.flac`、`歌.lrc`、`杂项文件夹/` → 库统计出现提示 → 整理 → 三者进入 `Unarchived/`，库根只剩白名单
3. 刷新扫描后 `Unarchived` 内曲目出现在管理表
4. 选中未归档曲目 → 归档状态报「歌曲不在归档目录 / 命名不规范」→ 整理 → 变为 `archived/{歌手}/{歌手} - 歌名.ext` 且状态 ✓
5. 带 `(Live)` 的文件归档后括号仍在；与无版本同名曲不冲突
6. 目标已存在时整理失败且原文件不动
7. 外挂歌词整理后仍在 `lrc/`，并与带版本的音频主名对齐
8. 「纳入库管理」复制到 `archived/{歌手}/`，命名符合规范
